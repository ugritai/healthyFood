DATA PREPARATION

Scripts are numbered in the order they are run. Arrows show the resulting
MongoDB collection. ES = healthy ageing (Envejecimiento Saludable).


FOOD TABLE

1. 1_FooDB_group_id.py: create the food group IDs -> FooDB_Grupos_ID
2. 2_Food_Simplified.py: add the group ID to the relevant Food fields -> Food_Simplificada


APPLIED PATHOPHYSIOLOGY TABLE

- Group IDs added in the same way as Food_Simplificada -> FAALD_FooDB_Id


FOOD-DISEASE RELATION DATASET TABLE

- Manual step: relations with imprecise sources are added, and objects that are
  not foods or not relevant are removed.
- Non-relevant fields are deleted, and "is_cause" and "is_treat" are merged into
  "suitable for disease".
- Food ID added -> FDR_FooDB_Id


FOOD-DISEASE TABLE

- FAALD_FooDB_Id and FDR_FooDB_Id are merged and the group ID is added
  -> Alimento_Enfermedad_Completa


FOODB TABLE

3. 3_FooDB_Pivoted.py: errors and missing values in FooDB are filled using the
   Food, Compounds and Nutrients tables. Only constituents whose source is USDA
   or DTU are kept, with the relevant fields. The table is pivoted so that each
   food holds all its compounds -> FooDB_Pivotado
4. 4_FooDB_Final.py: add the group ID -> FooDB_Alimento_Constituyentes


COOKING METHODS TABLE

- Created manually, no changes -> Cooking_Methods


HEALTHY AGEING TABLE

5. 5_ES_Range.py: compute the minimum and maximum of each healthy ageing aspect
   and split the range into 5 equal parts (0 = bad, 4 = good). Each value is
   assigned to its part -> ES_Rango, ES_min_max
- Manual step: assign each object of the original healthy ageing table to its
  foods or food groups -> ES_FooDB
6. 6_ES_Complete.py: merge ES_Rango with ES_FooDB -> ES_Alterada
7. 7_ES_Final.py: split foods and groups into separate documents to simplify
   the Neo4j queries -> ES_Final
